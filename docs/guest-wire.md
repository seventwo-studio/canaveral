# Guest protocol 1

Status: executable guest core; host routing, Swift integration, native boot and acceptance remain outstanding. Apple Virtualization and KubeVirt remain the backends. No Python production agent is introduced.

Transport: one AF_VSOCK stream on port 1024, accepted only from HOST_CID (2). One session per launch, no reconnect authority. Every frame is a four-byte unsigned big-endian JSON byte length (1..1048576), then UTF-8 JSON. Unknown fields, invalid types, noncanonical UUIDs and versions other than 1 fail closed. See `canaveral-guest-protocol` for exact field names. All numeric values are integers within JavaScript's safe range.

Host sends `hello`: version, binding {leaseId, memberId, revision (>0), bootAttempt (UUID), bundleDigest (lowercase SHA256 hex)}, remainingMs (>0). This binding must exactly match `/etc/canaveral/launch.json`, provisioned by the trusted launcher through an immutable per-launch config. It is not sufficient to supply an arbitrary hello. The launcher must authenticate the VM identity and bind the accepted stream to its native authorization before sending hello. Host CID restricts transport origin, not tenant authentication. Guest root can subvert guest enforcement; the native VM deadline guard remains the ultimate fence.

Host samples a conservative remaining duration after deducting transport/publication latency and safety margin; never send host absolute monotonic time. Guest applies it to local CLOCK_BOOTTIME (includes suspend). `renew` repeats the entire binding, with a strictly higher revision, before expiry. Expiry/disconnect/protocol error are sticky and end the session; no reconnect restores authority. `ready` echoes the accepted binding after separate successful `/bin/sh -c 'exit 0'`, `/usr/bin/git --version`, `/usr/local/bin/node --version`, `/usr/bin/python3 --version` probes. Debian sh does not implement --version. Each probe has its own argv and exit-code check; version output is checked against the immutable launch tool pins.

`exec`: version, id (canonical UUID), argv (nonempty strings), cwd (absolute beneath /workspace), env (string map), timeoutMs (>0). One active exec, stdin closed, environment cleared with a fixed PATH and supplied env; no host shell interpolation. Exec UUIDs must be strictly increasing by UUID bytes within the session, permitting replay rejection with bounded state and no execution-count cap. `credit`: version, bytes (1..1048576); outstanding credit is capped at 1048576 and counts decoded output bytes. Credit is session-wide and initially zero. `cancel`: version, id. Invalid/overlapping commands close the session. No implicit replay.

Guest `output`: version, id, stream (`stdout` or `stderr`), seq (zero-based across both streams per exec), data (standard padded base64). `exit`: version, id, status (nullable integer), signal (nullable integer), timedOut, durationMs, stdoutBytes, stderrBytes, terminationConfirmed. A null status/signal with terminationConfirmed=false is an unknown receipt, never release proof. Confirmed receipts require group termination and reaping, including descendants; guest kill alone never proves native VM release. Output is drained before exit, with byte counts for emitted bytes. Backpressure stalls output and completion, never expiry/cancel/disconnect supervision. Fixed-size queues and pipes bound memory; there is no total-output cap.

The initial workspace is tmpfs with an explicit byte capacity in launch.json; it is disposable, volatile, and not persistent storage. Block workspaces are deferred until strict path, fresh disposable identity, expected size and ownership evidence are implemented. No code formats a guessed or retained device.
