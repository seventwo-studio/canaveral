# Linux agent boot bundle v1

This slice provides a Rust PID1 agent, framing, lease enforcement and disposable process fixtures. It does not implement actual guest commands through the TypeScript route, Swift boot integration, native acceptance, or a usable end-to-end runtime. Apple Virtualization and KubeVirt remain the intended backends. Existing EFI/raw image compatibility remains unchanged for future integration. Python is only a preinstalled guest coding tool in this path.

## Bundle contract

`canaveral_guest_protocol::bundle::Manifest` is the executable schema and verifier. Required fields: version=1, id, revision (positive safe integer), arch=`arm64`, kernel {path,sha256,size}, initrd (same artifact object or null), rootfs (same artifact object), commandLine (exact trusted string), agentVsockPort=1024, protocol=1, toolVersions. Paths are relative beneath the bundle directory; sizes are bytes and SHA256 strings are lowercase hex. File verification rejects escapes, changed sizes and changed digests. Verify artifacts from a trusted, immutable directory; the verifier does not protect a concurrently attacker-writable bundle.

The kernel is an **uncompressed ARM64 Linux Image**, not EFI, PE, bzImage or gzip. The root filesystem is read-only EROFS. `initrd` is optional for the format; bootstrap requirements can make it necessary for a particular launcher. Neither this schema nor a successful hash check proves a kernel or filesystem boots.

`image.digest` is SHA256 of canonical manifest bytes: recursively sorted object keys, UTF-8 serde_json serialization, no insignificant whitespace or trailing newline, integer-only numeric fields. Null initrd is retained. The manifest does not contain its own digest. Paths and commandLine participate in the digest. Swift must use these exact canonicalization rules and verify all artifact sizes/digests before starting a VM. Guest authorization is a separately bound launch identity, not a host-clock timestamp. See [guest wire protocol](guest-wire.md).

## Trusted per-launch configuration

Before executing `/sbin/canaveral-guest-agent` as PID1, the trusted bootstrap must provide `/etc/canaveral/launch.json` as a separate read-only per-launch mount. It contains `binding` (leaseId, memberId, revision, bootAttempt, bundleDigest), `workspaceBytes` (16MiB..1GiB) and `toolVersions` with exact nonempty expected output substrings for git, node and python3. The launcher owns this configuration and the VM's native deadline guard. Do not embed this per-launch file in the hashed rootfs or initrd: including the bundle digest there would create a circular digest. Immutable configuration delivery from a separate trusted read-only launch medium is an outstanding Swift/KubeVirt bootstrap integration gate; this slice does not implement that provisioning. Never derive trusted scope from an unauthenticated hello.

Rootfs must already be mounted read-only, with mount points `/proc`, `/sys`, `/dev`, `/tmp`, `/run`, `/workspace` and `/etc/canaveral` precreated. Trusted bootstrap retains PID1 when switching root and executing the agent. The agent mounts proc/sysfs/devtmpfs and bounded tmpfs filesystems, validates root read-only, probes tools separately, listens on vsock 1024, accepts only host CID 2 and never accepts a replacement session. Production entry refuses every non-Linux or non-PID1 invocation; there is no stdio host-exec mode.

Initial workspace: disposable tmpfs, uid/gid 1000, explicit byte bound, nosuid/nodev. Child commands run as uid/gid 1000 with no supplementary groups, closed stdin and a cleared environment. This is volatile storage; workspace block-device formatting is absent. A later block workspace needs a strict device path, fresh disposable identity, expected size and durable ownership evidence before any destructive operation. Retained or arbitrary `/dev/vdb` must never be guessed or formatted.

The agent owns the guest PID namespace. Commands get separate process groups; production PID1 also kills all its namespace descendants on termination, including escaped groups, and reaps children before confirming a receipt. Unconfirmed termination or lost receipts require native fencing and recovery. Guest receipts cannot authorize VM release or replacement. Fixtures use owned disposable children and do not exercise namespace-wide production kills.

## Image recipe (authoring contract; not executed)

A release builder must supply all these inputs, without defaults: Debian snapshot timestamp and signed Release digest/trust root; exact arm64 package versions and SHA256 values for bash, coreutils, git, ca-certificates, python3 and transitive packages; official Node `v24.11.0` linux-arm64 tarball SHA256 and signature verification material; Rust `1.99.1` toolchain/target archive SHA256 values; kernel source version/archive SHA256, committed config and patch digests; EROFS tool version/digest; bootstrap source/digest and trusted configuration-medium contract. Unknown checksums are **required inputs**, not placeholder pins or floating defaults. Fixture version values in unit tests are synthetic, never release inputs.

1. In an isolated authorized release builder, verify the pinned Debian snapshot metadata and every package digest before extracting packages into a fresh staging root. Do not install packages at boot. Include /bin/sh, Git, CA certificates, Python and all shared libraries. Fix locale, timezone, file order, ownership and SOURCE_DATE_EPOCH to explicit release inputs.
2. Verify the official pinned Node tarball; extract Node to `/usr/local/bin/node` with its support files. Run separate argv probes and check each exit code and expected version. A compound shell command's final status is not proof that all tools work.
3. Build `canaveral-guest-agent` from the public source revision and Cargo.lock using Rust 1.99.1 and `aarch64-unknown-linux-musl`, `--locked --release`. Verify the resulting ELF is static; copy it as `/sbin/canaveral-guest-agent`. No Python production daemon or host executable bridge belongs in this root.
4. Build the pinned minimal kernel with virtio MMIO/PCI, virtio block, virtio vsock transport, EROFS, ext4, tmpfs, procfs, sysfs and devtmpfs **built in**, plus the selected architecture/console/bootstrap requirements. Include PID namespace support. Produce uncompressed `arch/arm64/boot/Image`. EROFS root must be mounted `ro`; ext4 support does not authorize formatting any workspace device.
5. Precreate mount points and uid/gid 1000 metadata; assemble deterministic EROFS using the pinned tool and fixed metadata. If needed, produce a deterministic bootstrap initrd from audited source. Keep per-launch configuration external to hashed artifacts. Package no private credentials, retained disks or parent repository history.
6. Record artifact paths, actual byte sizes and computed hashes, exact kernel command line and all tool pins in manifest v1. Canonicalize and compute image.digest. Publish only after a separate authorized boot/ownership/expiry/disconnect/backpressure acceptance run on each backend.

No image, container, VM, package download, signing, enrollment or deployment was performed for this slice. Portable workspace CI compiles stubs on non-Linux and runs real unprivileged disposable child fixtures on Linux. Source tests cover framing, authority, canonical digest, corruption, process output, exit, timeout, cancel, replay and stalled-reader expiry; they do not establish native boot performance or acceptance.
