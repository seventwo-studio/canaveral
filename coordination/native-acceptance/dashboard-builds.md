# Native dashboard build acceptance

Run `dashboardBuilds` from the PR61 disposable native dashboard adapter with the PR60 verified ARM64 bundle and signed helper. The trial needs two separate account logins, the private trial directory, and the dashboard TLS ingress used by the browser preview trial. Build the current coordination TypeScript and use the matching dashboard assets before starting the controller.

Supply the adapter's admission and cleanup callbacks. Resolve the submitted build ID to its lease using `SELECT lease FROM previews WHERE id=? AND mode='build'` against the private database. Start the satellite for that admitted lease. The cleanup callback must observe controller cleanup, successful satellite exit, helper and owned VM process exit, removal of the machine directory, workspace and relay, and zero domain reservations. Supply a restart callback that closes the first dashboard, waits for its close event, then creates a new dashboard server with the same database and controller configuration. The browser opens fresh authenticated contexts after restart.

The success case uploads a directory containing a Node program and a sibling JSON input under `src/site/`. The program reads the input, squares its value, and writes an HTML page. The browser retrieves the page through the authenticated dashboard after cleanup and verifies its exact bytes and SHA-256. Two further builds exercise a nonzero exit and owner cancellation of a running command. Keep credentials, raw private databases, browser profiles and operator diagnostics outside the repository.

## 2026-11-18 observations

The disposable controller and native ARM64 Apple Virtualization satellite used the [PR60 bundle and signed helper](pr60-native-preview.md). Before launch, the operator checked the manifest, all three boot payloads and the helper against their recorded SHA-256 values. The adapter verified the helper signature and signing requirement.

Chromium submitted the nested directory through the dashboard build form. Guest Node executed `node src/site/build.cjs` and exited 0. After automatic release and independent cleanup, the owner downloaded `index.html` from the dashboard. Its 54 bytes matched the host expectation and SHA-256 `8ffc1d5b50bf8376bde77ba30dfc3d4051869bd09cd38386a26779b4545bdaf6`. The same download link worked in a fresh authenticated browser context after closing and recreating the dashboard server with its original SQLite database. This exercised a dashboard server restart within the same harness process. The second account was denied detail, artifact and cancellation requests before and after restart.

A program that exited 17 reached `failed`. Owner cancellation of a running Node command reached `stopped`. Neither case exposed an artifact. For success, failure and cancellation, the controller reported complete cleanup and zero domain reservations, the satellite exited successfully, the observed helper and owned VM processes were gone, and the machine directory, workspace and relay were removed. The stopped, cleaned and released journal flags were set. The retained artifact and disposable evidence database were outside the released VM storage.
